# DataLoader Explained: What, Why & Where It Belongs!

This example shows what DataLoaders are, why you should use them, and where they belong in a Hot Chocolate project. It uses Green Donut DataLoaders in a small product catalog API backed by PostgreSQL and Entity Framework Core.

- Video: [https://www.youtube.com/watch?v=gVIxde5nlWE](https://www.youtube.com/watch?v=gVIxde5nlWE)
- Episode page: [https://chillicream.com/videos/2025-02-19-dataloader-explained](https://chillicream.com/videos/2025-02-19-dataloader-explained)

## Hot Chocolate version

This example uses Hot Chocolate `15.1.0-p.5` (`HotChocolate.AspNetCore`, `HotChocolate.Data`, `HotChocolate.Types.Analyzers`) with Green Donut DataLoaders generated by the source generator. The package versions are pinned in `Directory.Packages.props`.

## Prerequisites

- The .NET SDK, as pinned by the `global.json` of the repository root. The project targets `net9.0`.
- Docker, to run PostgreSQL with `compose.yml`.

## Run the example

From the example folder:

```bash
docker compose up -d
dotnet run --project src/Catalog.API
```

The `compose.yml` starts PostgreSQL (with user `admin` and password `root`) on port 5432 and pgAdmin on port 5050. The API reads the connection string `CatalogDB` from `appsettings.json`. On startup it applies the EF Core migrations and, if the catalog is empty, seeds it from `src/Catalog.API/Migrations/catalog.json`.

The GraphQL endpoint is served at `/graphql`. With the `http` launch profile in `src/Catalog.API/Properties/launchSettings.json`, that is `http://localhost:5224/graphql`.
